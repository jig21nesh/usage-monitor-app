# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this
project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Repository bootstrap: project rules, Architecture Decision Records, README, MIT license,
  contributing, security and code of conduct documents (#1).
- Scaffold: `UsageMonitorCore` Swift package with domain models, provider, credential, HTTP,
  keychain, file-system, settings and sleeper protocols, the `UsageMonitorModel` poll loop with
  per-provider backoff and diagnostics, log redaction, a thin SwiftUI menu bar app shell, XcodeGen
  project spec, SwiftLint configuration, coverage gate script and GitHub Actions CI (#1).
- Claude provider: reads the Claude Code keychain login and maps the OAuth usage endpoint's
  session, weekly and per-model windows (#2).
- OpenAI provider: reads the Codex CLI login file and maps the ChatGPT usage endpoint's 5-hour
  and weekly windows plus per-model limits (#3).
- Grok provider (experimental): reads the Grok Build CLI login file and maps the billing
  endpoint's weekly credit usage (#6).
- GitHub Copilot provider: reads the GitHub CLI login (keychain or `hosts.yml`) and maps the
  monthly premium-request quota plus metered chat and completions (#17).
- OpenCode Go provider: reads the OpenCode login file and maps the Go plan's rolling, weekly and
  monthly windows (#17).
- Cursor provider (experimental): reads Cursor's local token store read-only and maps included
  and on-demand usage for the billing cycle (#18).
- Muse Code provider (experimental): reads the Muse Code CLI login and maps its 5-hour and
  weekly windows; the API key the endpoint returns is never kept; polled at most every 15
  minutes (#16).
- Polling hardening: refresh on wake from sleep, reset-time formatting, redacted diagnostics
  report (#4); per-provider minimum poll interval (#14).
- App UI: onboarding, menu bar panel with usage bars, Settings with Accounts, Providers, Refresh
  and Diagnostics tabs, launch at login, XCUITest coverage (#11).
- Diagnostics "Copy report" button, percent style setting (used or left), and wake-from-sleep
  refresh wired into the app (#12).
- App icon: three glowing gauge rings on an indigo-to-teal squircle, generated by
  `scripts/generate-app-icon.swift` at all ten macOS sizes (#9).
- About window with version, Curious Pi Labs information and links to the website, source,
  issue tracker and licence (#19).
- Colour-coded menu bar icon: green, orange or red by the tracked provider's session limit
  (thresholds default 60% and 80%), grey when unknown or stale, with a monochrome option; new
  Settings > Menu bar tab for the tracked provider and thresholds (#14, #19).
- Distribution: `scripts/build-dmg.sh` builds a DMG (Developer ID signed and notarised when
  credentials exist, ad-hoc otherwise) and a tag-triggered release workflow publishes it; see
  `docs/RELEASING.md` (#15).
- Repository hygiene: README, pinned CI actions, UI-test and markdown-lint jobs, Dependabot for
  GitHub Actions, issue and pull request templates, CODEOWNERS (#5).

### Changed

- A fresh install enables Claude, OpenAI and Grok; the Welcome window then enables exactly the
  providers whose login it detects (#14, #19).
- ADR 0003 amended: read-only POST is allowed for idempotent usage RPCs (Cursor, Muse Code),
  endpoints that return a credential must discard it, and providers may declare a poll floor
  (#14).
- App Sandbox read-only exceptions extended to the GitHub CLI, Copilot CLI, Cursor, Muse Code
  and OpenCode credential paths; Release builds no longer inject `get-task-allow` (#14).

### Fixed

- Document the real Grok token lifetime (about six hours) and the re-link workaround (#7).
- Diagnostics table lists the registered providers instead of every provider case (#14).
- Fewer keychain consent dialogs: each credential is read once and kept in process memory until
  it expires, the vendor rejects it, or you press **Re-link**, and start-up probes only the
  providers you enabled, so macOS asks at most once per launch per item instead of on every
  refresh (ADR 0002 amendment).
