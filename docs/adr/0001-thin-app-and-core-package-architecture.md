# ADR 0001: Thin app target plus a testable Core Swift package

Date: 2026-09-19
Status: Accepted

## Context

The product is a SwiftUI menu bar extra for macOS 26+ that polls three vendors every 1 to 15
minutes and renders progress bars. The project requires close to 90% test coverage. SwiftUI view
bodies cannot be unit tested without a third-party library (ViewInspector), and a single app
target mixes untestable view code with the logic that must be covered.

Options considered:

1. **Single app target** with view models inside it. Simple, but coverage is dragged down by
   view bodies and app lifecycle glue, and the app target can only be tested through
   `xcodebuild` with code signing.
2. **Thin app target plus a local Swift package (`UsageMonitorCore`)** that owns providers,
   credential readers, networking, polling, settings, formatting and observability. The package
   is tested with `swift test`, needs no signing, and the app target is reduced to scenes and
   views bound to one observable model.
3. **Multiple packages per feature.** More boundaries than a small utility needs.

## Decision

Adopt option 2.

- `App/` contains `@main`, the `MenuBarExtra` and `Settings` scenes and SwiftUI views only.
- `Packages/UsageMonitorCore` contains everything else, organised as `Domain`, `Providers/<Vendor>`,
  `Credentials`, `Networking`, `Polling`, `Settings`, `Formatting`, `Observability`.
- Every external effect sits behind a protocol with an in-memory fake in the test target:
  `HTTPClient`, `CredentialSource`, `KeychainReader`, `FileSystem`, `SettingsStore`, `Sleeper`.
- `UsageMonitorModel` (`@MainActor @Observable`) is the single UI-facing model. The app target
  uses default MainActor isolation; Core is nonisolated by default.
- The periodic poller is a `Task` loop that sleeps on `ContinuousClock` with tolerance, so it
  survives system sleep, coalesces with other timers and is cancellable. No `Timer`.
- The Xcode project is generated by XcodeGen from `project.yml` so the repository never carries
  a hand-maintained `pbxproj`.

## Consequences

- Coverage is measured and gated on the Core package (see ADR 0005). View bodies are covered by
  an XCUITest smoke suite instead.
- Adding a provider means adding one folder under `Providers/` with a credential source, a
  client call and a pure mapper, plus fixtures. No view code changes are needed beyond
  registering the provider in the live factory.
- Contributors need XcodeGen to open the project in Xcode; `swift test` on the package works
  without it.
